Warrant

An agent can already edit Jira. Warrant is how it proves it was allowed to.

Every tool that hands work to a model hits the same wall: permission is all or nothing. Grant it and you have given a model your whole backlog. Withhold it and the agent can only suggest.

Warrant makes permission an object. An agent asks for a warrant: a named operation, a frozen list of issue keys, a ceiling on actions, and an expiry. A person sees what it would touch before signing. A grant can be narrowed, never widened.

What makes it different

  • A frozen list, never a query. A JQL query can resolve to different issues tomorrow. A warrant names the keys, so what was approved is what runs.
  • Enforced where the write happens. Every change goes through one action handler. A write outside the warrant is refused there, not by the model's good behaviour.
  • A refusal is an event. It is recorded, it is queued for a person, and that person can approve the single change and take it back.
  • Expiry is read from the clock. Nothing sweeps expired warrants, so nothing can forget to.

How it works

  1. Ask. The agent requests a warrant for an operation and a list of issues.
  2. See. The card shows what the permission would touch, read live from Jira and Teamwork Graph: linked pull requests, comments, goals and blockers.
  3. Sign. A human narrows the list or the ceiling and signs. It cannot be widened afterwards.
  4. Run. Covered writes execute normally and land in one ledger, each with what is needed to reverse it.
  5. Refuse. Anything outside the warrant is refused with a reason and waits for a person.

Install

Warrant is a Forge app, distributed by installation link rather than the Atlassian Marketplace.

Install Warrant

You need to be a site or app administrator on a Jira Cloud site. The app asks for read:jira-work, write:jira-work, read:jira-user, storage:app, and three read-only Teamwork Graph scopes. It is free and unlicensed.

What it stores

Warrants, ledger entries and the approval queue are kept in Atlassian's hosted storage for your own installation. The app declares no outbound network permission, so it cannot send anything to us or to anyone else. See the privacy statement.

Support

Honest limits

  • Built for Jira Cloud only, on Forge. No Data Center.
  • Three operations today: transition, comment, assign.
  • Not on the Marketplace, so there is no listing, no billing and no review ticket.
  • It is a hackathon entry. Treat it as a working demonstration, not a supported product.
